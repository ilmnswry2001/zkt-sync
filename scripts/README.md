# وكيل مزامنة ZKTeco

يربط الوكيل جهاز ZKTeco المحلي بنظام الحضور عبر HTTPS. يجب تشغيله على حاسوب يعمل باستمرار، متصل بشبكة الجهاز المحلية وبالإنترنت. الجهاز لا يتصل بالسحابة مباشرةً؛ الوكيل يقرأ سجلاته ويرفعها للنظام.

## الإعداد لأول مرة

1. من صفحة **الأجهزة** في النظام، أضف الجهاز بالرقم التسلسلي الصحيح وأنشئ مفتاح ربط.
2. نزّل `agent.py` و`requirements.txt` من بطاقة **المزامنة السحابية التلقائية**، وضعهما في مجلد على الحاسوب المتصل بجهاز البصمة.
3. ثبّت Python 3.10 أو أحدث، وافتح PowerShell أو Terminal في المجلد ثم نفّذ:

```sh
python -m pip install -r requirements.txt
```

4. شغّل معالج الإعداد التفاعلي:

```sh
python agent.py --setup
```

أدخل IP الجهاز والرقم التسلسلي ورابط النظام المنشور ومفتاح الربط. ينشئ المعالج `agent_config.ini`. هذا الملف يحتوي مفتاحاً سرياً؛ لا تشاركه ولا ترفعه إلى GitHub. يمكن بدلاً من ذلك تنزيل ملف الإعداد من صفحة الأجهزة بعد إنشاء المفتاح. تتضمن المتطلبات حزمة المناطق الزمنية اللازمة لويندوز لضبط توقيت بغداد.

## اختبار وتشغيل

للتعامل مع الوكيل من قائمة عربية تفاعلية، شغّل:

```sh
python agent_ui.py
```

على Windows يمكن تشغيل `run_agent_ui.bat` بالنقر المزدوج.

الخيار الأول يتصل مباشرةً بعنوان IP، ويتعرف على الجهاز ويقرأ سجلاته دون الحاجة إلى إعداد مفتاح سحابي. يمكن حفظ نسخة CSV محلياً في `Documents/ZKTecoAttendance` لمراجعتها في Excel. تبقى سجلات الجهاز دون تعديل أو حذف. رفع السجلات إلى ERP عملية منفصلة وتتطلب إعداد الربط السحابي ومفتاح الجهاز.

تتيح القائمة أيضاً اختبار الخادم، وإعداد الربط السحابي، وتنفيذ مزامنة واحدة أو مستمرة بعد تأكيد وجهة الإرسال. تبقى أوامر `agent.py` المباشرة أدناه متاحة للتشغيل المجدول.

اختبر الاتصال بالجهاز وخادم النظام قبل التشغيل:

```sh
python agent.py --check
```

ابدأ الرفع المستمر، أو نفّذ دورة واحدة:

```sh
python agent.py
python agent.py --once
```

يعرض الوكيل حالة الاتصال ونتيجة الرفع في الطرفية، ويحفظ السجل في `agent.log`. يقرأ الجهاز عبر TCP 4370 افتراضياً ويرفع الحركات كل خمس دقائق. يخزن الحركات غير المرسلة في `agent_queue.sqlite3`، ولا يحذفها إلا بعد إقرار النظام باستلامها. عند فشل الاتصال يعيد المحاولة تلقائياً مع زيادة مدة الانتظار.

على Windows، يمكن إنشاء مهمة في Task Scheduler لتشغيل `python.exe` مع الوسيط `agent.py` عند بدء الحاسوب، مع تحديد مجلد الوكيل في **Start in** وتفعيل إعادة التشغيل عند الفشل. على Linux يمكن تشغيله كخدمة systemd مع `Restart=always`.

## تشغيل عدة أجهزة معاً

من صفحة **الأجهزة**، استخدم **تنزيل وكيل جميع الأجهزة** لإنشاء ملف واحد يتضمن إعدادات الأجهزة النشطة ومفاتيح ربطها. يؤدي ذلك إلى تدوير مفاتيح تلك الأجهزة، فتتوقف الملفات الأقدم عن العمل. شغّل الملف المنزّل على حاسوب الشبكة؛ يفحص اتصال TCP على المنفذ 4370، ويبدأ الأجهزة المتاحة بالتوازي، ويتجاوز غير المتاحة مؤقتاً ثم يعيد فحصها. يعرض الطرفية باللغة الإنجليزية، ويظل زر **«سحب الآن»** في الموقع يطلب السجلات من وكيل الجهاز المتصل.

يحتوي الملف المنزّل على مفاتيح سرية؛ خزّنه في مكان آمن، ولا تشاركه أو ترفعه إلى GitHub.

لإدارة إعدادات يدوية منفصلة بدلاً من تنزيل الملف الموحّد، يمكن استخدام الطريقة التالية:

أنشئ مجلداً لكل جهاز داخل `scripts/agents/`، وضع إعداد الجهاز الذي نزّلته من صفحة الأجهزة باسم `agent_config.ini` داخله، مثلاً `scripts/agents/main-gate/agent_config.ini`. كرر ذلك لكل جهاز مع مفتاحه وإعداداته الخاصة. ثم شغّل من مجلد `scripts`:

```sh
python run_all_agents.py
```

يشغّل الملف وكيلاً مستقلاً لكل إعداد بالتوازي، ويعيد تشغيل الوكيل إذا توقف. تظل أوامر **«سحب الآن»** من الموقع متاحة لكل جهاز. أوقف الجميع بـ `Ctrl+C`. احتفظ بملفات الإعداد سرية؛ فهي تحتوي مفاتيح الربط.

يمكن تمرير مسار إعدادات آخر بعد الأمر، مثل `python agent.py --check D:\\ZKTAgent\\agent_config.ini`. إذا غُيّر مفتاح الجهاز أو أُلغي، أنشئ مفتاحاً جديداً ونزّل إعداداً جديداً؛ المفتاح السابق يتوقف فور تدويره.
