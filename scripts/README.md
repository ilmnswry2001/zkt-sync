# وكيل مزامنة ZKTeco

يربط الوكيل جهاز ZKTeco المحلي بنظام الحضور عبر HTTPS. يجب تشغيله على حاسوب يعمل باستمرار، متصل بشبكة الجهاز المحلية وبالإنترنت. الجهاز لا يتصل بالسحابة مباشرةً؛ الوكيل يقرأ سجلاته ويرفعها للنظام.

## الإعداد لأول مرة

1. من صفحة **الأجهزة** في النظام، أضف الجهاز بالرقم التسلسلي الصحيح وأنشئ مفتاح ربط.
2. نزّل `agent.py` و`requirements.txt` من بطاقة **المزامنة السحابية التلقائية**، وضعهما في مجلد على الحاسوب المتصل بجهاز البصمة.
3. ثبّت Python 3.10 أو أحدث، وافتح PowerShell أو Terminal في المجلد ثم نفّذ:

```sh
python -m pip install -r requirements.txt
```

4. شغّل معالج الإعداد التفاعلي:

```sh
python agent.py --setup
```

أدخل IP الجهاز والرقم التسلسلي ورابط النظام المنشور ومفتاح الربط. ينشئ المعالج `agent_config.ini`. هذا الملف يحتوي مفتاحاً سرياً؛ لا تشاركه ولا ترفعه إلى GitHub. يمكن بدلاً من ذلك تنزيل ملف الإعداد من صفحة الأجهزة بعد إنشاء المفتاح. تتضمن المتطلبات حزمة المناطق الزمنية اللازمة لويندوز لضبط توقيت بغداد.

## اختبار وتشغيل

اختبر الاتصال بالجهاز وخادم النظام قبل التشغيل:

```sh
python agent.py --check
```

ابدأ الرفع المستمر، أو نفّذ دورة واحدة:

```sh
python agent.py
python agent.py --once
```

يعرض الوكيل حالة الاتصال ونتيجة الرفع في الطرفية، ويحفظ السجل في `agent.log`. يقرأ الجهاز عبر TCP 4370 افتراضياً ويرفع الحركات كل خمس دقائق. يخزن الحركات غير المرسلة في `agent_queue.sqlite3`، ولا يحذفها إلا بعد إقرار النظام باستلامها. عند فشل الاتصال يعيد المحاولة تلقائياً مع زيادة مدة الانتظار.

على Windows، يمكن إنشاء مهمة في Task Scheduler لتشغيل `python.exe` مع الوسيط `agent.py` عند بدء الحاسوب، مع تحديد مجلد الوكيل في **Start in** وتفعيل إعادة التشغيل عند الفشل. على Linux يمكن تشغيله كخدمة systemd مع `Restart=always`.

يمكن تمرير مسار إعدادات آخر بعد الأمر، مثل `python agent.py --check D:\\ZKTAgent\\agent_config.ini`. إذا غُيّر مفتاح الجهاز أو أُلغي، أنشئ مفتاحاً جديداً ونزّل إعداداً جديداً؛ المفتاح السابق يتوقف فور تدويره.
