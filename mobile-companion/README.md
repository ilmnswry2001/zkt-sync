# تطبيق سحب البصمة بالهاتف

يدعم التطبيق أندرويد 8.0 فأحدث. يقرأ سجلات `ATT_LOG` عبر TCP أو UDP (المنفذ الافتراضي 4370) ويتحقق من الرقم التسلسلي قبل سحب الحركات. يستخدم توقيت بغداد ما لم يحدد المستخدم UTC. طريقة القراءة مستندة إلى [مرجع pyzk لبروتوكول ZKTeco](https://github.com/fananimi/pyzk/blob/master/zk/base.py).

1. يختار مدير النظام الجهاز من «سحب البصمة بالهاتف»، ويحدد بريد المشرف المسجّل، ثم ينزّل `zkteco-mobile-agent.json` ويسلّمه للمشرف المعني. يحتوي الملف على تصريح خاص بالجهاز والمشرف ينتهي بعد 30 يومًا ويمكن لمدير النظام إلغاؤه.
2. يستورد المشرف الملف من التطبيق ويتأكد من عنوان ERP والرقم التسلسلي، ثم يضبط عنوان IP والمنفذ ومفتاح اتصال الجهاز عند الحاجة. زر «اختبار اتصال الجهاز» يوضح البروتوكول المستخدم. يمكن اختيار TCP أو UDP أو الوضع التلقائي.
3. يضغط المشرف «سحب الحركات الآن». تُحفظ الدفعات في مساحة خاصة مشفّرة بمفتاح Android Keystore قبل الرفع. يرفع الوكيل الدفعات عند عودة الإنترنت وهو مفتوح، ويوفر زرًا لإعادة الإرسال. يمكن استيراد إعداد حديث للجهاز والمشرف نفسيهما إذا انتهى التصريح.

تُرسل الدفعات إلى `POST /api/public/zk-sync` عبر HTTPS باستخدام مفتاح الهاتف مع توقيع HMAC. يحمل كل جزء معرف دفعة ثابتًا حتى عند إعادة الإرسال. يدعم القارئ سجلات ZKTeco ذات 8 و16 و40 بايت. التجربة الميدانية تعتمد على توافق طراز الجهاز وبرنامجه الثابت مع هذا البروتوكول.

## البناء والتوقيع

يحتاج البناء على Windows إلى JDK 17 وAndroid SDK Platform 35 وBuild Tools 35. استعمل مفتاح PKCS#12 مخصصًا للتطبيق وملف كلمة مرور خارج المستودع. يُستخدم مفتاح الإصدار نفسه لتحديث تثبيتات المشرفين.

```powershell
./mobile-companion/build.ps1 -Jdk $jdk -Platform $platform -BuildTools $buildTools `
  -SigningKey $keyStore -SigningPasswordFile $passwordFile
```

يتحقق السكربت من توقيع APK وينسخه إلى `public/downloads/ZKTeco-Mobile-Companion.apk` الذي تستعمله صفحة التنزيل. عند تحديث الإصدار، حدّث رقم الإصدار في `AndroidManifest.xml` و`src/lib/mobile-sync.ts`.

يتطلب تشغيل المزامنة تطبيق `20261119160000_mobile_device_sync.sql` على قاعدة Supabase التابعة للنظام.
